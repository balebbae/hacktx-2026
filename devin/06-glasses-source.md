Meta's hosted docs MCP server is `https://mcp.developer.meta.com/wearables`; use it for API questions, and mirror Meta's `samples/CameraAccess` and `samples/BirdSpotter` in https://github.com/facebook/meta-wearables-dat-ios. ## Goal
A `FrameSource` that streams the glasses camera into the perception pipeline, with a mock-device path that works in a DEBUG Simulator build.

## Package and plist
- SPM `https://github.com/facebook/meta-wearables-dat-ios`, **exact tag `1.0.1`**; link `MWDATCore` and `MWDATCamera` to the app target; `MWDATMockDevice` too, but every use is inside `#if DEBUG`; `MWDATInputs` optional.
- Info.plist (S1 already added most of it; verify): `CFBundleURLTypes` scheme `familiar`; `MWDAT` dictionary `{AppLinkURLScheme: "familiar://", MetaAppID: "0", ClientToken: "0", TeamID: "$(DEVELOPMENT_TEAM)"}`; `NSBluetoothAlwaysUsageDescription`; `UIBackgroundModes` includes `bluetooth-central`, `bluetooth-peripheral`, `external-accessory`, `processing`, `audio`; `UISupportedExternalAccessoryProtocols` = [`com.meta.ar.wearable`] — this selects **Bluetooth Classic transport**. Do **not** add the Wi-Fi keys (`NSBonjourServices`, the HotspotConfiguration entitlement): with both sets present the SDK picks Classic anyway, and on Wi-Fi transport the glasses mute app audio during a stream. Write `docs/WIFI_TRANSPORT.md` describing the Wi-Fi keys as a video-quality fallback with phone-speaker audio.

## Flow (mirror the CameraAccess sample)
`try Wearables.configure()` once at app start (`.alreadyConfigured` is fine) → `GlassesRegistrationView` with a "Connect glasses" button → `try await Wearables.shared.startRegistration()` (opens the Meta AI app) → in the app's `.onOpenURL`, if the URL has a `metaWearablesAction` query item, `Task { _ = try await Wearables.shared.handleUrl(url) }` → observe `registrationStateStream()` until `.registered` → `if Wearables.shared.checkPermissionStatus(.camera) != .granted { try await Wearables.shared.requestPermission(.camera) }` → `let session = try Wearables.shared.createSession(deviceSelector: AutoDeviceSelector(wearables: Wearables.shared))`; create `stateStream()` and `errorStream()` **before** `try session.start()` → on `.started`: `let camera = try session.addCamera(config: StreamConfiguration(videoCodec: .hvc1, resolution: .medium, frameRate: 24))` → `camera.stream.videoFramePublisher.listen { frame in … }.store(in: tokenBag)` (keep every token in a `ListenerTokenBag`) → `camera.stream.start()`. Decode `frame.sampleBuffer` (HEVC) with a `VTDecompressionSession` configured for software decoding so the session survives backgrounding (copy the approach of the sample's `VideoFrameDecoder.swift`) → 32BGRA `CVPixelBuffer` → `Frame(timestamp: host time mapped from the sample PTS at the first frame, orientation: .up, horizontalFOVDegrees: 53, verticalFOVDegrees: 85)` (frames are portrait 504×896). Stream states: `.streaming` does not guarantee frames; show "waiting for frames" until the first one arrives (can take ~12 s). Handle `StreamError` cases `thermalHot`, `batteryLow`, `peakPowerLimit`, `hingesClosed` by stopping and telling the user; folding the glasses stops the session; `.raw` codec is foreground-only, so stay on `.hvc1`. Device state through `Wearables.shared.deviceForIdentifier(id)?.addDeviceStateListener` → battery %, donned, hinge, thermal → a Readiness row. If frames arrive at `.low`, the SDK dropped quality under bandwidth pressure; log it.
- **Audio coordination (with S3's `AudioEngineController`):** while a glasses session is active the app must keep the HFP route closed (opening it ends the session). Expose `GlassesFrameSource.isStreaming` and set the controller's `glassesStreamActive` so Route B is refused during a stream. Route A (phone mic + A2DP out) is the default.
- Optional **`GlassesStreamAudioInput: AudioInput`**: `StreamConfiguration(videoCodec: .hvc1, audioCodec: .pcm(sampleRate: .rate16000, numberOfChannels: 1), resolution: .medium, frameRate: 24)` → `stream.audioFramePublisher.listen { frame in frame.pcmBuffer / frame.presentationTimeStamp }` → `AudioChunk`s. Not beamformed, ~200 ms behind video, dev-only feature. Behind a Settings toggle.
- Optional **gestures** (`MWDATInputs`): `let inputs = try session.addInputs(configuration: InputsConfiguration(sources: [.captouch, .captureButton]))`; `for await event in inputs.events` → `.select` (double tap) → `Command.whoIsHere`; `.capture(.shortPress)` → `Command.rememberThem` (a double press emits `shortPress` then `doublePress`; debounce). Single tap and tap-and-hold are reserved by Meta. Publish through a `CommandSource`.

## Mock Device Kit (DEBUG only)
`MockDeviceKit.shared.enable(config: MockDeviceKitConfig(initiallyRegistered: true, initialPermissionsGranted: true))`; `let glasses = try MockDeviceKit.shared.pairGlasses(model: .rayBanMeta)`; power on, `unfold()`, `don()`; `glasses.services.camera.setCameraFeed(fileURL: <HEVC .mov>)` (**H.265 only**; the team commits `*_hevc.mov` fixtures; if none exist yet, create one with `ffmpeg -i enroll_marcus.mp4 -c:v libx265 -tag:v hvc1 -an enroll_marcus_hevc.mov`) or `setCameraFeed(cameraFacing: .back)` on a device. Then run the normal flow. Known issue #331: the iOS 27 Simulator may reach `.streaming` with no frames — prefer an iOS 26 simulator runtime; if frames never arrive, document it and rely on the human hardware pass.
